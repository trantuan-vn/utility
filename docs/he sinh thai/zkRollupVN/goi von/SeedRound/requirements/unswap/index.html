Hướng Dẫn Hiểu Kiến Trúc Phần Mềm Uniswap Interface

Đây là hướng dẫn chi tiết để hiểu kiến trúc phần mềm của Uniswap interface, một ứng dụng React-based frontend cho sàn giao dịch phi tập trung (DEX) Uniswap. Dự án sử dụng các thư viện như React, Redux, Apollo GraphQL, Wagmi, và Tamagui, với cấu trúc monorepo lớn, tập trung vào tính modular, reusable components, và state management phức tạp.

Bước 1: Hiểu cấu trúc thư mục tổng quát và entry points

Mục tiêu: Nắm tổng quan dự án để biết các phần chính và cách chúng tổ chức.

Hành động:

  • Xem file gốc: src/index.tsx (entry point chính), index.html (template HTML), và src/App.tsx (component root).
  • Phân loại thư mục:
    • src/: Chứa code chính.
      • components/: Components reusable (e.g., AccountDrawer/, Charts/).
      • hooks/: Custom hooks (e.g., useAccount.ts, useSwapCallback.tsx).
      • pages/: Các trang/route (e.g., Swap/, PoolDetails/).
      • state/: State management (e.g., swap/, user/).
      • utils/: Utilities (e.g., prices.ts, slippage.ts).
      • assets/: Tài nguyên tĩnh (images, svgs).
      • lib/: Thư viện nội bộ (e.g., hooks/routing/).
      • nft/: NFT-related components.
      • theme/: Styling (Tamagui config).
    • public/: Tài nguyên public (images, fonts, PDFs).
    • functions/: Serverless functions (e.g., API cho images).
    • scripts/: Build/test scripts (e.g., generate-sitemap.js).
    • tests/: Tests (Cypress, Playwright, Vitest).
  • Mối liên hệ: Entry points import từ các thư mục khác (e.g., App.tsx import NavBar từ components/NavBar/). Sử dụng VS Code để "Go to Definition".

Thời gian ước tính: 30-60 phút.

Bước 2: Phân tích state management và data flow

Mục tiêu: Hiểu cách state được quản lý (local/global) cho transactions, user prefs, và blockchain data.

Hành động:

  • Tập trung vào src/state/:
    • Reducers: application/reducer.ts, user/reducer.ts, swap/SwapContext.tsx.
    • Actions: lists/actions.ts, global/actions.ts.
    • Sagas: sagas/root.ts, sagas/transactions/swapSaga.ts.
    • Hooks: state/hooks.ts (selectors).
  • Xem src/state/index.ts (combine reducers) và src/App.tsx (Redux Provider).
  • Theo dõi data flow: State swap (state/swap/) được dùng trong pages/Swap/SwapContext.tsx, kết nối với useSwapCallback.tsx.
  • Mối liên hệ: State kết nối với UI qua hooks (e.g., useAccount.ts lấy state từ state/user/). Sagas gọi API từ appGraphql/ (e.g., AllV3TicksQuery.ts). Dùng Redux DevTools để debug.

Thời gian ước tính: 1-2 giờ.

Bước 3: Theo dõi routing và pages

Mục tiêu: Hiểu navigation và routes trong SPA.

Hành động:

  • Xem src/pages/RouteDefinitions.tsx và routes.test.ts (React Router).
  • Khám phá pages:
    • pages/Swap/index.tsx: Trang swap, import CurrencyInputPanel.
    • pages/PoolDetails/index.tsx: Chi tiết pool, dùng GraphQL từ appGraphql/data/pools/.
    • pages/AddLiquidityV2/redirects.tsx: Handle legacy routes.
  • Xem components/NavBar/ (navigation).
  • Mối liên hệ: Pages import components (e.g., PoolDetails.tsx import PoolDetailsHeader.tsx, hooks như usePoolTickData.ts). Routes check state từ state/user/.

Thời gian ước tính: 1 giờ.

Bước 4: Khám phá components và hooks

Mục tiêu: Hiểu cách UI và logic được modular hóa.

Hành động:

  • Components: components/Swap/, components/Liquidity/ (e.g., ConfirmSwapModal.tsx).
  • Hooks: hooks/useSwapCallback.tsx, hooks/useAccount.ts. Xem tests như useMaxAmountIn.test.tsx.
  • Mối liên hệ: Components dùng hooks (e.g., SwapCurrencyInputPanel.tsx dùng useCurrencyBalance.ts). Hooks import utils (e.g., useSwapTaxes.ts dùng slippage.ts).

Thời gian ước tính: 1-2 giờ, tập trung vào swap hoặc liquidity.

Bước 5: Phân tích integrations (Web3, API, GraphQL)

Mục tiêu: Hiểu cách app kết nối với blockchain và backend.

Hành động:

  • Web3: src/connection/ (connectors), hooks/useConnect.tsx, wagmiConfig.ts.
  • GraphQL: src/appGraphql/ (e.g., Token.ts, apollo/client.ts).
  • API: functions/api/, lib/hooks/routing/.
  • Mối liên hệ: Hooks như useEthersProvider.ts dùng trong components (e.g., PoolDetails.tsx query GraphQL, render charts).

Thời gian ước tính: 1 giờ.

Bước 6: Xem tests, build scripts, và tools

Mục tiêu: Hiểu cách dự án được test và build.

Hành động:

  • Tests: src/test-utils/, e2e tests như pages/App.smoketest.e2e.test.ts.
  • Scripts: scripts/ (e.g., generate-sitemap.js), vite.config.mts.
  • Mối liên hệ: Tests mock dependencies (e.g., GraphQL ở playwright/mocks/), giúp theo dõi flow.

Thời gian ước tính: 30 phút, chạy npm test.

Bước 7: Tổng Hợp Và Tối Ưu Hóa Uniswap Interface

Mục tiêu: Tổng hợp kiến thứ, Xác định tối ưu hóa, Hiểu thực tế, Lý do quan trọng.

Hành động:

  • Tổng Hợp Luồng Dữ Liệu (Data Flow).
  • Đánh Giá Tối Ưu Hóa Hiệu Suất.
  • Đánh Giá Maintainability.
  • Đánh Giá Scalability (Multichain, New Features).
  • Debugging Một Flow Thực Tế (Swap Failure).

Thời gian ước tính: 1 giờ.

Bước 8: Theo dõi dependencies và vẽ diagram

Mục tiêu: Visualize mối liên hệ giữa files.

Hành động:

  • Sử dụng VS Code: Tìm kiếm import (e.g., useSwapCallback) hoặc extension "Graphviz".
  • Tool: madge src/ --image graph.svg.
  • Ví dụ flow: User click swap → pages/Swap/ → state update via state/swap/ → call API via sagas → render modal via components/ConfirmSwapModal/.

Thời gian ước tính: 1 giờ.
